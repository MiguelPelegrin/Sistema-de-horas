3. BACKEND SISTEMA CADASTRAMENTO
- Corrigido o construtor quebrado de UsuarioService.
- Corrigido o banco Flyway: a entidade Usuario usa a tabela usuario, mas a migração antiga criava dados_senhas. Isso foi alinhado.
- Corrigado o INSERT da migração V0002 para a tabela correta.
- Incluído o arquivo de configuração do Maven Wrapper que estava ausente nesse backend.

VALIDAÇÕES REALIZADAS
- Todos os arquivos JavaScript passaram por node --check.
- Foi feita uma varredura de referências relativas de HTML/CSS e não sobraram arquivos referenciados inexistentes.
- O Maven não pôde ser executado completamente neste ambiente porque os wrappers precisariam baixar o Maven da internet; a tentativa de download falhou por indisponibilidade de acesso ao repositório.
- A checagem direta com javac confirmou que não há mais o erro de sintaxe do construtor/conteúdo Java identificado anteriormente; as falhas restantes da compilação direta são apenas dependências externas do Spring/Jakarta/Lombok que não estão no classpath dessa checagem.

OBSERVAÇÃO
O projeto ainda contém dois backends separados (cronosystem e SistemaCadastramento). Eles não foram fundidos, porque isso mudaria a arquitetura original do projeto. Também não foi inventada uma integração entre o frontend e uma API que não existia no código enviado.
